# HW 2. Обучение GAN

## Задание

Необходимо реализовать и обучить GAN на датасете `CelebA`.

Основная часть:

- скачать датасет `CelebA`;
- реализовать `CSPup` блок;
- реализовать генератор GAN по заданной архитектурной схеме;
- обучить GAN;
- добиться сходимости и описать использованные приемы стабилизации.

## Дополнительное задание

Дополнительное задание от Бондаренко: сравнительный анализ типов нормализации в генераторе.

Нужно обучить и сравнить несколько версий модели при одинаковых параметрах обучения:

- `BatchNorm` как baseline для DCGAN;
- `InstanceNorm`;
- `LayerNorm` или вариант без нормализации.

В отчете требуется сравнить:

- стабильность `loss`;
- время до сходимости;
- визуальное качество генерации;
- наблюдаемые проблемы: `mode collapse`, артефакты, шум;
- особенности обучения.

## Датасет

Используется `CelebA` в формате `ImageFolder`.

Источник: `Yuehao/celeba` на Hugging Face, архив `img_align_celeba.zip`.

Данные подготовлены локально:

- архив: `data/celeba_raw/img_align_celeba.zip`;
- изображения: `data/celeba/faces`;
- количество изображений: `202599`;
- типы изображений: `.jpg`, выровненные и обрезанные лица.

Скрипты ожидают явно подготовленную директорию через `--data-root`. Если путь отсутствует или не является директорией, запуск завершается с ошибкой.

Ожидаемый формат:

```text
data_root/
  faces/
    image_000001.jpg
    image_000002.jpg
```

Preprocessing:

- `Resize(64)`;
- `CenterCrop(64)`;
- `ToTensor`;
- нормализация в диапазон `[-1, 1]`.

## Структура

- `src/data.py` - загрузка изображений через `ImageFolder`;
- `src/models.py` - `CSPup`, генератор и дискриминатор;
- `src/train.py` - цикл обучения GAN;
- `src/utils.py` - seed, device, сохранение графиков и JSON;
- `scripts/train_gan.py` - запуск одного эксперимента;
- `scripts/run_norm_experiments.py` - запуск серии экспериментов по нормализациям;
- `artifacts/` - результаты обучения, графики и сгенерированные изображения;
- `README.md` - отчет по заданию и экспериментам.

## Реализация

Генератор получает шум `z` размера `latent_dim x 1 x 1` и строит изображение `3 x 64 x 64`.
Вместо обычной цепочки `ConvTranspose2d` для upsampling используется блок `CSPup`.

Поддерживаемые варианты нормализации в генераторе:

- `batch`;
- `instance`;
- `layer`;
- `none`.

Дискриминатор построен в стиле DCGAN: последовательность `Conv2d`, `BatchNorm2d`, `LeakyReLU`, выход - один logit на изображение.
Для обучения используется `BCEWithLogitsLoss`, поэтому `Sigmoid` в дискриминаторе не добавляется.

Текущая архитектура рассчитана на изображения `64 x 64`. Параметр `base_channels` должен быть положительным и четным, иначе запуск завершается с ошибкой.

## Запуск

Один эксперимент:

```bash
uv run python -m hw_2.scripts.train_gan \
  --data-root data/celeba \
  --output-dir hw_2/artifacts/batch \
  --norm batch \
  --epochs 5 \
  --batch-size 128 \
  --device mps
```

На Mac можно оставить `--device auto`: при доступном Apple Silicon GPU будет выбран `mps`.

Серия для дополнительного задания:

```bash
uv run python -m hw_2.scripts.run_norm_experiments \
  --data-root data/celeba \
  --output-root hw_2/artifacts/norm_experiments \
  --norms batch instance none \
  --epochs 10 \
  --batch-size 128 \
  --device mps
```

Для быстрого smoke-run можно добавить:

```bash
--max-items 64 --max-batches 2 --epochs 1 --base-channels 4 --latent-dim 8
```

## Артефакты и метрики

Каждый запуск сохраняет в свою директорию:

- `config.json` - параметры эксперимента: нормализация, seed, device, batch size, learning rate и ограничения subset;
- `losses.json` - значения по итерациям: `g_loss`, `d_loss`, `D(x)`, `D(G(z))` до и после обновления генератора;
- `metrics.json` - агрегаты по эпохам;
- `metrics.csv` - те же агрегаты в табличном формате;
- `summary.md` - краткий отчет по финальной эпохе;
- `train.log` - ход обучения, старт и итог каждой эпохи;
- `loss_plot.png` - график `G/D loss`;
- `samples_epoch_XXX.png` - генерации на фиксированном шуме;
- `generator_epoch_XXX.pt` - checkpoint генератора.

Метрики, график, summary, samples и checkpoint обновляются после каждой завершенной эпохи. Если запуск оборвется после эпохи, уже записанные результаты останутся пригодными для анализа.

Для серии нормализаций дополнительно создается общий `summary.md` в `output-root` с финальными метриками всех вариантов.

## Результаты на CelebA

Основной запуск выполнен на `CelebA` для трех вариантов нормализации в генераторе:

- `batch`;
- `instance`;
- `none`.

Параметры эксперимента:

- epochs: `10`;
- batch size: `128`;
- image size: `64`;
- latent dim: `100`;
- base channels: `64`;
- optimizer: `Adam`, `lr=0.0002`, `beta1=0.5`;
- device: `mps`;
- seed: `999`;
- output: `hw_2/artifacts/norm_experiments_10ep`.

Итоговые метрики последней эпохи:

| Norm | G loss | D loss | D(x) | D(G(z)) after |
| :--- | ---: | ---: | ---: | ---: |
| Batch Norm | `3.5902` | `0.5111` | `0.8251` | `0.0776` |
| Instance Norm | `4.5959` | `0.3088` | `0.8971` | `0.0421` |
| No Norm | `8.2661` | `0.1231` | `0.9614` | `0.0060` |

| Аспект | Batch Norm | Instance Norm | No Norm |
| :--- | :--- | :--- | :--- |
| Стабильность `loss` | Наиболее сбалансированный вариант: дискриминатор не полностью подавляет генератор. | Дискриминатор сильнее, чем в Batch Norm, но обучение не разваливается. | Явный дисбаланс: `D loss` падает слишком низко, `G loss` резко выше остальных. |
| Время до сходимости | Уже к поздним эпохам появляются разнообразные лица; 10 эпох достаточно для читаемых samples. | Сходится до узнаваемых лиц, но менее разнообразно. | Формально быстро стабилизируется в плохом режиме, но это не полезная сходимость. |
| Визуальное качество | Лучшее: лица разнообразные, больше деталей, меньше повторов. | Среднее: лица читаемые, но чаще заметны сглаженность, однотипность и артефакты цвета. | Худшее: сильные повторы одних и тех же лиц, пересветы и признаки mode collapse. |
| Наблюдаемые проблемы | Есть отдельные артефакты и искажения, но без выраженного mode collapse. | Есть цветовые артефакты и менее естественная текстура. | Mode collapse, малое разнообразие, часть samples почти дублируется. |
| Дополнительные заметки | Лучший вариант для итогового решения. | Рабочий вариант для сравнения, но уступает Batch Norm. | Нормализация в генераторе критична для стабильности этого DCGAN-подобного пайплайна. |

Итог: лучшим вариантом в проведенном протоколе оказался `BatchNorm`. `InstanceNorm` дает приемлемые результаты, но визуально уступает и сильнее смещает баланс в пользу дискриминатора. Вариант без нормализации показал выраженный `mode collapse`, поэтому для финальной модели не подходит.
